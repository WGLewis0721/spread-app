# Focus widget diagnostic candidate

This branch does not claim a fix. Main at e276f01 includes PR #230. The app commits through `SpreadFocusControls.apply`: save precedes the widget reload request. The widget rejects missing/undecodable sessions, disabled display, profile mismatch, or an off-screen reconciled session. The initial timer constructor can publish before the asynchronous first profile is noted; `noteActiveProfile` publishes again. This establishes a possible idle entry, not proof of why the observed phone remains idle. WidgetKit controls when reload requests are serviced. An activity may outlive its authoritative session; diagnostics count matches without recording identifiers.

## Capture and interpretation

Use a tethered iPhone and an existing device-log reader (for example `idevicesyslog` from libimobiledevice on Windows or Linux); filter for `SpreadFocusDiag` and save only those lines. Enable Developer Mode if iOS requires it for the development build. The operating system can suppress or delay log delivery, so absence of a line alone is not proof of a missing invocation. Do not share the full unfiltered device log: it may contain unrelated private data. Diagnostic lines contain timestamps, classifications, deadline, counts and booleans, never names, profile or session identifiers. `suite=available` means the UserDefaults initializer returned an object; it does not prove entitlement or cross-process visibility.

1. With widget display enabled, capture the idle widget and island, then start a 24-minute session in the foreground. Record wall-clock tap time, `save_complete`, `reload_requested`, `timer_timeline` and the time the widget visibly changes separately. Screenshot the app, island and widget; redact personal content. If present, `requested_matches_saved=true` plus decoded/match/enabled at `reload_requested` establishes app-side eligibility at that moment. Provider `storage`, `profile`, `enabled`, `phase`, `deadline` and `resolved` distinguish its view. A provider invocation with eligible running state but an idle screen points to rendering or a delayed visible update; no observed provider invocation does not by itself prove a WidgetKit failure.
2. Repeat with app backgrounded and terminated, and after relaunch. Test small, medium, large and Today medium. Compare deadlines and session match counts, and measure save latency and visible refresh latency separately. Countdown should move without further timeline invocations.
3. Pause from the Home Screen widget and separately from the expanded Dynamic Island or Lock Screen. Record whether the app itself pauses and whether the control icon or countdown changes. `intent_SetSpreadFocusPlayingIntent` records the widget toggle request and its Boolean; `intent_PauseSpreadFocusIntent` records the separate activity button. Compare `target_matches_saved`, `profile`, and `phase` with the subsequent `save_complete` and provider lines. An intent entry without a save can indicate a guard rejection; a save followed by a running display can indicate a refresh issue. Missing log lines are inconclusive because log capture can lose events. Then resume, forward, stop and cancel; exercise rapid taps and stale buttons. Switch profiles and confirm neither content nor controls cross profiles. Toggle widget display off and confirm privacy. Capture corresponding filtered lines and screenshots. Do not infer instantaneous reload guarantees.
4. For an island without a matching saved session, record `activity_refresh` counts and storage classification; do not invent a new session. If logs or screenshots conflict, retain the evidence and investigate before changing behavior.

The isolated defaults unit test checks diagnostic classification, decoding, profile comparison, opt-in and a running deadline; it does not execute WidgetKit or prove signed App Group access. The source test verifies save-before-publish ordering, not disk durability or refresh delivery. Rollback: revert this branch's commit; it changes no production timer behavior. Never merge or upload without authorization.
