# Lessons learned from Spread versions 2–7 and their preservation

These conclusions come from the user's recorded feedback, preserved requests and source/edit/export evidence. Recommendations below describe how to avoid the same rework; they do not guarantee a model's performance.

| Observation | Lesson | Apply next time |
| --- | --- | --- |
| The viewer responded to productivity advice before the app reveal. | A useful method gives the product an earned role in the story. | Explain the ritual first, then turn that same plan into the interface. |
| Animation, graphics and script were approved while voice revisions continued. | Revising approved layers adds avoidable risk. | Freeze accepted art and copy; change only the failed performance or timing layer. |
| A female voice still felt like the previous flat performance. | Voice identity and delivery are separate choices. | Compare short same-text auditions for articulation, energy and expression before recording the full film. |
| The user liked Hallie and Juno for different reasons. | Specific traits are more actionable than a celebrity comparison or “more energy.” | Keep a named preset identity; direct confidence, expressiveness, cadence and restraint separately. |
| Early takes were too soft and breathy; excitement labels alone did not settle the issue. | Prompt tags are requests, not reliable quality controls. | Listen to dry samples at matched level. Keep the successful complete recording as the reference. |
| The user heard “Boc” even though transcription recognized “box.” | ASR can miss an audible editing problem. | Keep consonant tails; listen to the word and its join in context. Do not cut directly from ASR timestamps. |
| Hallie's first half sounded like two run-on sentences. | A clean script is not a human performance. | Use distinct sentences, breath room and semantic sections; preserve rests instead of packing every gap. |
| The final “So” revision made the pivot work. | A small prosody edit can carry the emotional turn. | Change only the pivot. The approved beat is 0.455 seconds, measured approximately from speech gates; exact edit ranges are saved. |
| One good audition supplied planning advice, reveal and tagline in the full film. | Accepted audio is valuable source material. | Reuse complete successful sections and generate only missing phrases. Keep raw sources and an edit ledger. |
| Samples were initially hard to hear. | A file's existence is not successful delivery. | Provide a playable sample and confirm unmuted playback advances without media errors. |
| Several earlier Studio tabs showed stale compositions or timed out. | A running server or HTTP response does not prove a working preview. | Verify the exact project/cut in Studio; avoid adding repeated stale tabs. Keep the verified MP4 available when preview control fails. |
| Smoke rendering once logged a closed Chrome target during concurrent work. | Heavy parallel rendering can be fragile on a laptop. | Use the package's serial smoke command and modest full-render concurrency. Diagnose the actual error before repeating renders. |
| Windows could not find unzip, and the app's Vite wrapper could not spawn its executable shim. | Host environment problems can look like product regressions. | Check available executables; use a verified process-local workaround and record it. Keep unrelated app fixes separate. |
| Line endings initially interfered with byte inventory and Git checks. | Reproducibility includes text bytes and generated evidence. | Preserve original source with scoped attributes; write new generated evidence with explicit LF. Use the inventory command, not bulk manual hash replacement. |
| Original media needed retrieval from completed provider jobs. | Remote URLs and tool history are poor long-term storage. | Materialize accepted sources locally, retain safe job IDs/provenance, and exclude signed URLs and account identifiers from the repository. |

## What to repeat

Lock the brief → test a small audition → keep accepted recordings → build to actual speech → preview and correct only the failing interval → export and verify → preserve the complete handoff. The quality came from this review loop and precise feedback, not a single model or prompt.

The female v7 approval is recorded. The male companion was requested later and is technically verified. An App Store badge in a draft is not evidence that the application is listed or that the film is approved for publication.
